## A. Google Search / SEO (October 2026)

### A1. Rich result types: supported vs deprecated

**Currently listed in Google's Structured Data Gallery (VERIFIED, page last updated 2026-10-16, https://developers.google.com/search/docs/appearance/structured-data/search-gallery)** — 25 features: Article, Breadcrumb, Carousel (must be combined with another type), Course list, Dataset (Dataset Search only), Discussion forum, Education Q&A, Employer aggregate rating, Event, Image metadata, Job posting, Local business, Math solver, Movie, Organization, Product (merchant listing + product snippet), Profile page, Q&A, Recipe, Review snippet, Software app, Speakable, Subscription & paywalled content, Vacation rental, Video. No gallery entry is marked deprecated.

**Removed / deprecated (VERIFIED via Search Central changelog https://developers.google.com/search/updates):**
- **FAQ rich results — GONE.** Changelog 2026-05-08: "Added a deprecation notice to the FAQ rich result documentation… This feature will no longer appear in Google Search starting May 7, 2026." Changelog 2026-06-15: FAQ rich result documentation removed because "The FAQ rich result feature is no longer shown in Google Search results." The 2023 limitation (gov/health only) is now moot: the feature is off for every site. SECONDARY reports (The HOTH, inblog.ai, getpassionfruit) add that Search Console FAQ reporting and Rich Results Test support ended June 2026 and the Search Console API appearance filter in August 2026 — those exact tool-removal dates are not in the changelog excerpt I read; flag as SECONDARY. FAQPage markup is still valid schema.org and harmless, but earns nothing in Google Search.
- **HowTo** — removed September 2023 (SECONDARY recap; consistent with Google's 2023 announcement). No HowTo rich result on any surface.
- **Sitelinks search box** — retired 21 November 2024 (SECONDARY; consistent with Google's Nov 2024 announcement). `WebSite`/`SearchAction` markup is ignored for that feature (but `WebSite` is still a title-link signal, see A7).
- **Course info, Estimated salary, Learning video, Special announcement, Vehicle listing** — documentation removed 2025-09-09; "no longer appear in Search results" (VERIFIED changelog).
- **Practice problem** — deprecation notice 2025-11-05; docs removed 2026-01-06; removed from Search Console, Rich Results Test and search-appearance filters in January 2026 (VERIFIED changelog).
- **Book actions** — deprecation banner REMOVED 2025-11-05 because a Search feature still uses it (VERIFIED changelog). **ClaimReview** — got a June 2025 phase-out banner (SECONDARY); it is not in the current gallery list, so treat as retired.
- **Discover "Follow"** — removed 2025-11-19 (VERIFIED changelog).
- Still supported and recently *expanded*: Discussion Forum and QAPage (more properties added 2026-03-24), VideoObject (`creator` property added 2026-09-24), Merchant listing (`hasAdultConsideration` 2026-05-20; `category` 2026-07-07; shipping policies 2025-11-12). Profile page, Organization, LocalBusiness, Article, Event, JobPosting, Course list, Software app, Speakable: all still in gallery (VERIFIED 2026-10-16).

**Review / aggregateRating self-serving rule — STILL DISALLOWED (VERIFIED, https://developers.google.com/search/docs/appearance/structured-data/review-snippet):** "If the entity that's being reviewed controls the reviews about itself, their pages that use `LocalBusiness` or any other type of `Organization` structured data are ineligible for star review feature." Example given: a review of entity A placed on entity A's own site, including via an embedded third-party widget. LocalBusiness and Organization review snippets are only for sites that capture reviews *about other* businesses/organizations. Changelog 2026-07-24 added a guideline against "fake and undisclosed incentivized reviews"; 2025-11-12 clarified to avoid multiple ways of indicating what is being reviewed. Supported review-snippet types: Book, Course list, Event, Local business (third-party only), Movie, Product, Recipe, Software App, CreativeWorkSeason/Series, Episode, Game, MediaObject, MusicPlaylist, MusicRecording, Organization (third-party only); employers use EmployerAggregateRating.

### A2. Core Web Vitals

**VERIFIED (https://web.dev/articles/vitals, last updated 2024-10-31):** The three stable Core Web Vitals are unchanged — **LCP ≤ 2.5 s**, **INP ≤ 200 ms**, **CLS ≤ 0.1**, assessed at the 75th percentile of page loads, split mobile/desktop. (Needs-improvement/poor bands remain LCP 2.5–4.0 s / >4.0 s, INP 200–500 ms / >500 ms, CLS 0.1–0.25 / >0.25 — shown in the page's threshold images; standard since 2024.) INP replaced FID on 12 March 2024.
- **No new Core Web Vital in 2025–2026.** web.dev's lifecycle rule: stable CWV change at most once a year; candidates sit in "pending" ≥6 months first. No "pending" metric is announced on the vitals page. Searches for "Engagement Reliability", "Smoothness", or a Long-Animation-Frames-based CWV found no web.dev/Chrome announcement; the only "Engagement Reliability" mention is a single marketing blog (ideafueled.com) with no citation — **UNVERIFIED, treat as fabricated**. Only concrete 2026 change reported: better soft-navigation CWV measurement for SPAs in Chrome 151 (SECONDARY, nitropack/rivuletiq).
- Google Search's page-experience guidance still points at CWV as a (minor) signal; "good page experience" is listed among fundamentals in the AI-features doc (VERIFIED, see A3).

### A3. AI Overviews, AI Mode, AI crawlers, llms.txt

**Google official guidance — two docs (both VERIFIED):**
1. **"AI features and your website"** — https://developers.google.com/search/docs/appearance/ai-features (last updated 2025-12-10). Key quotes: "There are no additional requirements to appear in AI Overviews or AI Mode, nor other special optimizations necessary." Only requirement: page is indexed and eligible to show with a snippet. "You don't need to create new machine readable files, AI text files, or markup to appear in these features." Both features use "query fan-out" (multiple related searches) and so "display a wider and more diverse set of helpful links" than classic Search; AI Overviews and AI Mode may use different models so their links differ; AI Overviews only show when judged additive. Controls: robots.txt for Googlebot; `nosnippet`, `data-nosnippet`, `max-snippet`, `noindex` limit what appears; Google-Extended limits "AI training and grounding in some of Google's other systems" (NOT Search AI features). Traffic from AI features is reported in Search Console Performance under the "Web" search type (no separate AI filter). Google claims clicks from AI-Overview pages are "higher quality".
2. **"Optimizing your website for generative AI features on Google Search"** — https://developers.google.com/search/docs/fundamentals/ai-optimization-guide (published 2026-05-15 per changelog + Search Central blog https://developers.google.com/search/blog/2026/05/a-new-resource-for-optimizing; page last updated 2026-07-10). Core line: AEO/GEO is "still SEO". Non-commodity content: "Create the content yourself based on what you know about the topic"; avoid content that "could originate from anyone". Merchant Center + Business Profile "can help your products and services to be visible in both AI responses and other Google Search results". Support text with high-quality images/video. Explicit "misconceptions you can ignore": llms.txt / machine-readable files ("Google Search itself doesn't use them" — neither help nor harm), content chunking ("There's no ideal page length"), rewriting for AI / chasing long-tail phrasing, inauthentic brand mentions, AI-specific markup (no special schema.org for AI; normal structured data still helps rich results). Has an AI-agents section (agents complete tasks like bookings; mentions Universal Commerce Protocol, UCP).
- Changelog 2026-06-15: "Added a note that Google Search doesn't use llms.txt files, which won't affect rankings either way" (VERIFIED).
- Changelog 2026-05-15: "Clarified that spam policies apply to generative AI responses in Search" (VERIFIED); spam-policies intro now says spam includes attempts to manipulate generative AI responses in Google Search.
- **Preferred sources** (VERIFIED, https://developers.google.com/search/docs/appearance/preferred-sources, last updated 2026-09-18): readers pick sites in Search settings; "preferred" badge in Top Stories (global) and, since 2026-05-27, in AI Overviews and AI Mode. Domain/subdomain level only (not /blog subdirectories). Google offers a JS button (`google-add-preferred-source-btn`) or deeplink to google.com/preferences/source. Changelog 2026-09-16 also added a "Search profile badge" guide. SECONDARY (Thurrott/9to5Google): Google says users are 2x as likely to click a preferred source; >345k sources selected.

**Reach (SECONDARY, from Google I/O 2026 keynote coverage and Q2-2026 earnings reporting):** AI Overviews >2.5 billion monthly users (I/O 2026; previously "2B+" since May 2025), in 200+ countries/territories, 40+ languages; AI Mode >1 billion monthly users (reaffirmed Q2 2026 earnings call). Claim that a Search Console "AI Citations report" launched May 2026 appears only on one marketing blog — **UNVERIFIED / likely false**; Google's own doc (Dec 2025) says AI traffic is folded into the Web search type.

### A5. Sitemaps and IndexNow

**VERIFIED (https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap, last updated 2026-07-08):** "Google ignores `<priority>` and `<changefreq>` values." ### A6. 2025–2026 Google updates, spam policies, E-E-A-T

**Spam policies (VERIFIED, https://developers.google.com/search/docs/essentials/spam-policies, last updated 2026-08-28).** Headings: Cloaking, Doorway abuse, Expired domain abuse, Hacked content, Hidden text/link abuse, Keyword stuffing, Link spam, Machine-generated traffic, Malicious practices, Misleading functionality (incl. "back button hijacking", added 2026-04-13), Scaled content abuse, Scraping, **Site reputation policy** (renamed from "site reputation abuse"), Sneaky redirects, Thin affiliation, User-generated spam. Definitions: scaled content abuse = "many pages are generated for the primary purpose of manipulating search rankings" (AI, human or mixed — AI itself is not a violation); expired domain abuse = expired domain "purchased and repurposed primarily to manipulate search rankings"; site reputation policy = "third-party content is published on a host site mainly because of that host's already-established ranking signals". **EEA change (2026-08-28, VERIFIED):** outside the EEA violating pages may get a manual action; inside the EEA such pages are treated as separate from the main domain and are not subject to manual action, with a reconsideration + alternative dispute resolution process. Spam intro now explicitly covers manipulating generative AI responses (2026-05-15). Spam reports may now be used for manual actions (2026-04-14/23).

**Ranking updates 2025–2026 (SECONDARY, consistent across SEJ/SERoundtable/keywordseverywhere; Search Status Dashboard URL I tried returned 404):** March 2026 core update 27 Mar–8 Apr 2026; May 2026 core update 21 May–2 Jun 2026; February 2026 Discover core update (confirmed by changelog 2026-02-05 "Discover" guidance); spam updates March 2026 (~19.5 h), June 2026, August 2026 (ended 21 Aug), September 2026 (started 24 Sep; completion not confirmed). Google states 2026 spam updates target scaled content abuse via SpamBrain, not link spam or site reputation. Changelog 2025-12-09 added a note that smaller core updates can affect sites between major core updates (VERIFIED). **AI content & E-E-A-T (VERIFIED, https://developers.google.com/search/docs/fundamentals/using-gen-ai-content, last updated 2026-10-01; changelog: aligned with rater guidelines):** AI is fine for research/structuring; "manually factcheck and review all AI-generated content for accuracy and trustworthiness before publishing" — explicitly including titles, meta descriptions, structured data and image alt text; mass AI pages without value = scaled content abuse; consider disclosing how content was created; Merchant Center requires IPTC `DigitalSourceType` metadata on AI images and labelling of AI-generated product titles/descriptions. ### A7. Titles and meta descriptions

**Title links (VERIFIED, https://developers.google.com/search/docs/appearance/title-link, last updated 2025-12-10):** Google gives **no character or pixel limit** — "no limit on how long a title element can be", but titles are truncated to device width. Google rewrites when it detects: half-empty titles, obsolete dates, inaccurate titles, micro-boilerplate (near-identical titles across pages), no clear main title, language/script mismatch, duplicated site names. Sources for generated titles: `<title>`, main visual title, headings (`<h1>`), `og:title`, prominent text, anchor text, inbound link text, `WebSite` structured data. Best practice: unique, descriptive, concise, brand with site name + delimiter, h1 matches title, same language as content. Industry rule of thumb (SECONDARY, not Google): ~50–60 chars / ~600 px desktop; mobile can show 70–80; rewrite rates 61–76% in studies.

**Meta descriptions / snippets (VERIFIED, https://developers.google.com/search/docs/appearance/snippet, last updated 2026-04-20):** "There's no limit on how long a meta description can be" but it's truncated to fit; snippets are built mainly from page content and the meta description is used when it describes the page better. Unique per page, include concrete details (author/date/specs), programmatic generation OK for large sites, avoid keyword lists. New 2026-04-20 section on "read more" deep links: keep content visible without expanders/tabs, don't force scroll position with JS, keep hash fragments intact.

## B. India DPDP Act 2023 and DPDP Rules 2025 (status 2026-10-20)

### B1. Status of the Rules and phased timeline

- **Rules notified:** Digital Personal Data Protection Rules, 2025, **G.S.R. 846(E), 13 November 2025** (MeitY, under s.40); Act commencement notification G.S.R. 843(E) same date; corrigendum G.S.R. 892(E), 10 Dec 2025 (SECONDARY but consistent across law-firm sources; MeitY site returned 403 to fetch; rule text read from dpdpa.com mirror "as of 13/11/2025" which links the official English PDF). Draft was January 2025.
- **Phased commencement (Rule 1; VERIFIED via rule mirror + multiple law-firm sources):**
  - **Phase 1 — 13 Nov 2025 (LIVE):** Rules 1, 2 (definitions) and 17–21 (Data Protection Board: proceedings, search-cum-selection committee, members' terms, salaries, appeals to TDSAT).
  - **Phase 2 — 13 Nov 2026 (in ~3 weeks):** Rule 4 — Consent Manager registration (First Schedule Part A conditions: company incorporated in India, net worth not less than ₹2 crore, capability, fit-and-proper, independent certification; Part B obligations incl. 7-year consent records, data unreadable to the CM, no subcontracting). (VERIFIED on schedule1 mirror.) Some sources write 14 Nov 2026 / 14 May 2027 — off-by-one interpretation; the gazette counts from 13 Nov 2025.
  - **Phase 3 — 13 May 2027:** Rules 3, 5–16, 22, 23 — notice, State processing, security safeguards, breach intimation, retention/erasure, contact info, children's and disability consent, SDF obligations, rights, cross-border, exemptions. **As of Oct 2026 none of the substantive obligations in B3 are legally in force; penalties cannot yet be levied for them.**
- **Acceleration proposal:** MeitY floated (stakeholder meeting 22 Jan 2026, comments by 4 Feb 2026; Business Standard, SS Rana, APAC News) cutting the 18-month window to 12 months (i.e. 13 Nov 2026), at least for SDFs, and making cross-border restrictions and information-call powers immediate. **Not notified as of 20 Oct 2026** (no gazette found; multiple trackers list it as "proposed, not gazetted"). Flag: watch MeitY for a notification; if it lands, Phase 3 moves to 13 Nov 2026.
- **Data Protection Board:** constituted in law; MeitY circular 6 May 2026 invited applications for Chairperson + 4 Members (citizen, ≥55 yrs); further notification 6 June 2026; search-cum-selection committee chaired by Cabinet Secretary. **No appointment confirmed as of Oct 2026** (LiveLaw analysis; no gazette found) — UNVERIFIED whether appointed in Sept/Oct. Consent Manager registration portal: not announced.
- **Latest instrument:** DPDP (Removal of Difficulties) Order, 2026 — S.O. 5458(E), 5 Oct 2026, gazetted 7 Oct 2026 (India Briefing, SS Rana, KSK, CyberPeace). Two textual fixes: s.9(1) "child or **of** a person with disability"; s.10(2)(c)(ii) "audit" → "data audit". Clarificatory only.
- **Significant Data Fiduciaries:** none notified yet (no notification found). SDF duties (Rule 13, VERIFIED mirror): DPIA + data audit "once in every period of twelve months", report of significant observations to Board, algorithmic due diligence, localisation of government-specified data categories (incl. traffic data); India-resident DPO comes from s.10 of the Act.
- **Cross-border (Rule 15, VERIFIED mirror):** default = transfer allowed; Central Government "may, by general or special order" impose requirements on making data available to a foreign State or entities under its control. No orders issued yet (none found).

### B3. Practical obligations for a small startup / clinic website (effective 13 May 2027 unless accelerated; build now)

**Consent notice (Rule 3, VERIFIED mirror):** must (a) be "presented and be understandable independently of any other information" — i.e. standalone, not just a link to a long privacy policy; (b) in "clear and plain language", give at minimum "(i) an itemised description of such personal data; and (ii) the specified purpose or purposes of, and specific description of the goods or services to be provided or uses to be enabled by, such processing"; (c) give the link to the Fiduciary's website/app and describe the means to "(i) withdraw her consent, with the ease of doing so being comparable to that with which such consent was given; (ii) exercise her rights under the Act; and (iii) make a complaint to the Board." Consent must be free, specific, informed, unconditional, unambiguous, with clear affirmative action, limited to the stated purpose (Act s.6). **Languages:** Act s.5(3)/s.6(3) — the Data Principal may access the notice/consent request in English or any of the 22 Eighth-Schedule languages (so offer at least English + regional language; Hindi/Gujarati etc. on request). Pre-existing data (collected before commencement) needs a notice "as soon as reasonably practicable".

**Withdrawal:** as easy as giving consent; after withdrawal stop processing within a reasonable time and have processors stop; retention only if another law requires.

**Contact person (Rule 9, VERIFIED mirror):** prominently publish on website/app, and in every response to a rights communication, the business contact information of the DPO "if applicable" (SDFs only) or of "a person who is able to answer on behalf of the Data Fiduciary" questions about processing. Also the Act's s.13 grievance officer requirement.

**Rights requests and grievances (Rule 14, VERIFIED mirror):** publish the means (form/email/portal) and identifiers (username/customer ID/email) required to make a request; respond under a published grievance-redressal system "within a reasonable period not exceeding ninety days"; support nomination of another individual. Rights: access summary, correction/completion/updating, erasure, grievance redressal, nomination. Data Principal must exhaust the Fiduciary's grievance route before the Board.

**Security safeguards (Rule 6, VERIFIED mirror):** at minimum encryption/obfuscation/masking/virtual tokens; access controls; logging + monitoring + review of access; backups/continuity; **retain logs and personal data for one year** (unless other law says otherwise); contractual security terms with processors; technical and organisational measures. Processors only under valid contract; fiduciary remains liable.

**Breach notification (Rule 7, VERIFIED mirror):** on becoming aware, (1) **"without delay"** tell each affected Data Principal via user account or registered contact, in concise plain language: nature/extent/timing/location of the breach; likely consequences for them; mitigation taken/proposed; safety measures they can take; business contact for queries. (2) **"without delay"** tell the Board: nature, extent, timing, location, likely impact. (3) **Within 72 hours** of becoming aware (extendable by Board on written request) send the Board: updated detailed info, broad facts and circumstances/reasons, mitigation, findings on the person who caused it, remedial measures to prevent recurrence, and a report of the intimations given to Data Principals. Applies to *every* breach (no materiality threshold). Separate from CERT-In's 6-hour incident reporting under the 2022 directions.

**Retention / erasure (Rule 8 + Third Schedule, VERIFIED mirror):** general rule — erase when purpose served or consent withdrawn, unless retention required by law. The Third Schedule default periods apply only to **large platforms**: e-commerce entity ≥ 2 crore registered users in India; online gaming intermediary ≥ 50 lakh; social media intermediary ≥ 2 crore — for all purposes except account access and stored-value tokens, data must be erased **3 years** after the user last approached the Fiduciary (or Rules commencement, whichever later), with a notice **at least 48 hours** before erasure telling the user it will be deleted unless they log in/engage/exercise rights. A clinic or small startup is below these thresholds; it should publish its own retention schedule (medical-records retention under clinical-establishment rules / EHR standards overrides erasure) and keep processing logs ≥1 year (Rule 6/8(3)).

**Children (Rule 10, VERIFIED mirror):** child = under 18. Before processing a child's data obtain **verifiable parental consent**, verifying the parent is an identifiable adult using (a) reliable identity/age details already held, or (b) details voluntarily provided or a **virtual token** issued by an authorised entity, e.g. via **DigiLocker**. Illustrations cover registered vs unregistered parents. No tracking, behavioural monitoring or targeted ads at children (Act s.9); Fourth Schedule exempts certain classes (e.g. healthcare professionals/clinical establishments, educational institutions, childcare) from parts of s.9 for specific purposes — a clinic treating minors should check Fourth Schedule exemptions (SECONDARY; not read directly). Persons with disabilities: lawful guardian consent (Rule 11).

**Checklist for the skill (all due by 13 May 2027, possibly 13 Nov 2026):** standalone itemised consent notice at each collection point (forms, booking, WhatsApp intake, cookies/analytics); consent log with timestamp/version; withdrawal control of equal ease; rights-request channel + ≤90-day grievance SLA; published contact person/DPO; processor contracts (hosting, CRM, analytics, payment, WhatsApp API); security baseline incl. 1-year logs; breach runbook with "without delay" + 72-hour templates; retention schedule; parental-consent flow for under-18 patients/users; Eighth-Schedule language option; readiness to register with a Consent Manager (optional for small sites).
